# Статья

`sessions_rows.csv` — исходная выгрузка Supabase; не изменяется обработчиком.

Первичная нормализация и аудит (Python 3, без сторонних библиотек):

```bash
python normalize_sessions.py
```

Результаты в `processed/`:

- `sessions_normalized.csv` — все исходные столбцы и строки плюс даты UTC/UTC+05:00,
  длительность, расшифровка завершения, разность весов и флаги качества.
- `daily_coverage.csv` — календарь регистрации, включая дни без записей.
- `gaps.csv` — интервалы отсутствия записей по системе и устройствам;
  причина и участие инженеров не подтверждены.
- `audit.json` — параметры обработки, контрольная сумма исходника и счётчики.
- `audit_ru.md` — результаты, ограничения и план подготовки данных для статьи.

`weight_delta_source_units` — точная разность исходных чисел.
`weight_delta_kg_assumed` — та же разность при допущении о килограммах из текущей
прошивки; для подозрительного масштаба оставлена пустой. Это не готовый надой.
`quality_flags` — несколько признаков через `;`, не автоматическое решение об
исключении записи. Исторические единицы требуют сверки с версиями прошивки.

На этом этапе ничего не дописано: `provenance=observed`, `is_imputed=false`.
Некорректные часы не заменяются временем поступления на сервер. Отсутствующие
RFID не угадываются. Дни без записей не считаются подтверждёнными отказами.
Для восстановления отдельных пропусков нужны реестр коров, расписание доений
и журнал обслуживания; оценки следует хранить отдельно от исходных наблюдений.
